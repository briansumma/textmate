# Requirements: TextMate (Personal Fork)

**Defined:** 2026-10-19
**Core Value:** TextMate builds for Apple Silicon, launches, opens and saves files, and runs its bundle commands on the current macOS. Other working features keep working.

## Definitions

- **Current macOS:** macOS 26.7.1 (build 25G241). Xcode 27.1 (27A9275) with SDK 27.0.
- **Clean checkout:** a new, empty directory created by `git clone --recursive` of `develop` at the commit under test. It contains no build output and no `local.rave`.
- **Launches:** the built app starts, shows its main window, and writes no new crash report to `~/Library/Logs/DiagnosticReports` within 30 seconds of starting.
- **Bundle set:** the 8 bundles in `~/Library/Application Support/TextMate/Bundles` (C, HTML, Perl, Python, Shell Script 2, Shell Script, Text, Themes) plus the bundled `Avian.tmbundle`. The 67 managed bundles are excluded (see Open decisions).
- **Removed:** the code path, menu item, and preference control are absent from the built app. A test proves it.
- **Built app:** the `TextMate.app` produced by `ninja TextMate`. Locate it with `find . -name TextMate.app -path "*/build*" -print -quit`.

## v1 Requirements

Requirements for the personal fork. No new features are in scope. Each requirement names a test command and a pass rule.

### Build

- [ ] **BUILD-01**: Build `TextMate.app` for arm64 on the current macOS with the current Xcode from a clean checkout
  - Test: `ninja TextMate` exits 0. Then `lipo -archs "$(find . -path '*TextMate.app/Contents/MacOS/TextMate' -print -quit)"`.
  - Pass: the build exits 0, and `lipo` prints `arm64`.

- [ ] **BUILD-02**: `configure` finds Homebrew dependencies under `/opt/homebrew` without hand-editing `local.rave`
  - Precondition: `boost`, `capnp`, `google-sparsehash`, `multimarkdown`, `ragel`, and `ninja` are installed through Homebrew. Versions are recorded in the README Building section.
  - Test: `brew list --versions boost capnp google-sparsehash multimarkdown ragel ninja`, then `./configure`, then `grep -c /usr/local local.rave`.
  - Pass: every package prints a version, `configure` exits 0, and `grep` prints `0`. `local.rave` is generated by `configure` and is not edited by hand.

- [ ] **BUILD-03**: Submodules initialize with one documented command
  - Document: `README.md`, section "Building". The command is `git submodule update --init --recursive`. The section is added as part of this work.
  - Test: `git submodule status | grep -c '^-'`.
  - Pass: the command prints `0`, and the README section names the command exactly.

- [ ] **BUILD-04**: Deployment target is macOS 26.7.1 only; the 10.12 floor is removed. The `-std=c++2a` flag is unchanged unless the build fails.
  - Test: `plutil -extract LSMinimumSystemVersion raw <built Info.plist>`, then `vtool -show-build <built TextMate executable>`.
  - Pass: `plutil` prints `26.7.1`, and `vtool` reports the minimum OS version 26.7.1. Compare the numbers, since `vtool` formats them on its own.

- [ ] **BUILD-05**: Deprecated APIs are migrated only where the build or a RUN test fails on the current macOS. A migration must not change behavior.
  - Call sites in scope: `WebView` in `Frameworks/HTMLOutput`, `NSURLConnection` in `OakHTMLOutputView.mm:199`, and `NSTask.launchPath` in `Frameworks/SoftwareUpdate/src/SoftwareUpdate.mm:557` and `OakDownloadManager.mm`.
  - Test: for each call site, the RUN test that exercises it (RUN-03 to RUN-05) passes before and after the change.
  - Pass: each call site is unchanged with its RUN test passing, or migrated with the same RUN test passing. Any call site outside this list is an Open decision.

### Run

- [ ] **RUN-01**: The built app launches on the current macOS
  - Test: `open <built TextMate.app>`, wait 30 seconds, then `pgrep -x TextMate`. Then `find ~/Library/Logs/DiagnosticReports -newer <launch marker file> -name 'TextMate*'`.
  - Pass: `pgrep` prints a process ID, and `find` prints nothing. A launch dialog does not fail the test, but the dialog and its text are recorded in the test log.

- [ ] **RUN-02**: Opening, editing, and saving a file work
  - Test: create `runtest-utf8.txt` containing a known line. Open it in the built app with File > Open. Type a second line. Save. Then `shasum -a 256 runtest-utf8.txt`, and compare the result with the hash of the expected text recorded before the test.
  - Pass: the saved file matches the expected text, and the hash matches. Reopening the file shows both lines.

- [ ] **RUN-03**: Each bundle in the bundle set runs its commands
  - Test: for each bundle in the bundle set, run one command the bundle declares. Record the exit status and the output target. For a bundle with no commands, load one of its grammar, theme, or snippets in a new document.
  - Pass: each command exits 0 and its output appears in the target the command declares. Each bundle with no commands loads without error. A missing interpreter (for example Python or Perl) fails the test and is recorded as an environment failure.

- [ ] **RUN-04**: A bundle command whose output is HTML shows that output in the HTML output window
  - Test: run one command from `HTML.tmbundle` whose output is HTML.
  - Pass: the HTML output window opens and shows the rendered output. A blank window fails the test.

- [ ] **RUN-05**: The About window and the Preferences window open and show content. A changed preference persists.
  - Test: open About and Preferences. Change one preference. Quit the app. Relaunch it. Check the preference.
  - Pass: both windows show content, and the changed preference holds after relaunch.

### Update Check

- [ ] **UPD-01**: The app's online update check is removed. The app does not contact `api.textmate.org` for its own update check.
  - Test: check the menu bar for "Check for Update" and the Preferences pane for "Check Now". Then capture DNS during a run of RUN-01 to RUN-05, for example `sudo tcpdump -l -n -i any port 53 | grep api.textmate.org`.
  - Pass: neither the menu item nor the button exists, and the capture prints no `api.textmate.org` lookup. The bundle index, the bundle updater, and the crash upload are covered only by the Open decisions below.

### Signing

- [ ] **SIGN-01**: The built app is ad-hoc signed and runs locally without notarization
  - Test: `codesign -dv --verbose=4 <built TextMate.app>`, then `codesign --verify --deep --strict <built TextMate.app>`. Then `grep -c APPLE_DEVELOPER_ID local.rave` and `git diff -- Applications/TextMate/Entitlements.plist`.
  - Pass: `codesign -dv` shows `Signature=adhoc` and no `TeamIdentifier` line. `codesign --verify` exits 0. `grep` prints `0`. The entitlements diff is empty. `spctl --assess` may reject an ad-hoc app, and that rejection is expected. RUN-01 must pass for "runs locally" to hold.
  - Note: `local-orig.rave` must not be copied into `local.rave`. That file sets a Developer ID identity and a notarize step.

## Cross-cutting checks

- **Regression:** run the test targets that build at the baseline commit `346b52b1`, using `ninja <framework>/test` for each framework with a `tests` directory. Record the pass and fail list on the first successful build. The list after the work must show no new failures.
- **Feature freeze:** `git diff 346b52b1 -- . ':(exclude).planning'` lists the changed files. Each changed file maps to one requirement ID in the commit message. Pass: no changed file lacks an ID.
- **Local only:** `git push` to `origin` fails, or `origin` is removed. Pass: no push reaches a remote.

## Out of Scope

| Feature | Reason |
|---------|--------|
| New features | User request: no features at this time |
| Intel (x86_64) builds | Target Mac is Apple Silicon only |
| Notarization and Developer ID signing | Personal use needs ad-hoc signing only |
| Public distribution or upstream release | Personal fork only |
| Remote hosting of the fork | Repository stays local for now |
| Security hardening (rmate remote mode, privileged helper, ATS) | Personal machine; revisit if the fork leaves this Mac |
| `disable-library-validation` entitlement | Stays unchanged; `Applications/TextMate/Entitlements.plist` is not edited. Same reason as security hardening |
| Any `CONCERNS.md` item not named in a requirement | Not in scope unless a requirement or an Open decision names it |
| Replacing legacy WebView or ODB code | Change only if a test under BUILD-05 requires it |

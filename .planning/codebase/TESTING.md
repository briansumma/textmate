# Testing Patterns

**Analysis Date:** 2026-10-19

## Test Framework

**Runner:**
- In-house runner generated by `bin/gen_test` (Ruby + ERB, runs under the macOS system Ruby per its shebang at `/System/Library/Frameworks/Ruby.framework/...`). It reads each test source, finds `void test_*()`, `void setup_*()`, and `void benchmark_*()` functions by regex, and emits a `main()` that runs them.
- `bin/CxxTest` is registered as a git submodule in `.gitmodules`, but neither `bin/gen_test` nor `bin/rave` references it. Do not write tests against CxxTest APIs.
- Test executables run on a GCD queue with a `CFRunLoop` (see `bin/gen_test`), so the runner works for both plain C++ and Objective-C++ tests.
- Config: `Frameworks/*/default.rave` (`tests` and `cxx_tests` lines), `bin/gen_test`.

**Assertion Library:**
- Built-in macros generated into every test translation unit by `bin/gen_test` (see the `OAK_ASSERT*` definitions around lines 100-120 of that file). There is no third-party assertion library.

**Run Commands:**

```bash
./configure                  # Bootstraps build.ninja (release config, per configure script)
ninja text/test              # Build and run one framework's tests (target name inferred from .tm_properties TM_NINJA_TARGET; confirm with: ninja -t targets all | grep /test)
ninja ns/test                # Same pattern for another framework
ninja -t clean               # Clean build outputs (README.md)
```

- The `<framework>/test` target name is derived from the file path by the `TM_NINJA_TARGET` rule in `.tm_properties`: `tests/t_*.{cc,mm}` maps to `${framework}/test`. Opening a test file in TextMate and pressing ⌘B runs that target (README.md, "Building").
- Runner flags (from `bin/gen_test` `write_usage`), passed to the generated test executable:

```bash
<test-binary> -v             # Print "N tests passed" on success
<test-binary> -P             # Disable parallel execution (default is parallel)
<test-binary> -m             # Time each test
<test-binary> -r 10          # Repeat each test 10 times
<test-binary> -b             # Run benchmark_* functions instead of tests
```

- The executable's output path depends on the build directory configured in `.tm_properties` (`TM_BUILD_DIR`). The path was not verified in this analysis.
- Watch mode: none. Coverage command: none (see Coverage).

## Test Coverage Summary

- **288** `test_*` functions across **25** test directories (24 under `Frameworks/`, 1 under `vendor/Onigmo/`). Counts per directory are listed in "Test Types" below.
- **23 frameworks** under `Frameworks/` have no `tests/` directory at all, including the UI frameworks `Frameworks/OakTextView`, `Frameworks/OakTabBarView`, `Frameworks/FileBrowser`, `Frameworks/DocumentWindow`, `Frameworks/Preferences`, `Frameworks/BundlesManager`, plus `Frameworks/encoding`, `Frameworks/OakFoundation`, `Frameworks/OakDebug`, and `Frameworks/undo`.
- **CI does not run tests.** `.github/workflows/build.yml` runs `ninja TextMate` only. `.travis.yml` runs `ninja TextMate` only. Tests are run by hand (or via the TextMate ⌘B shortcut).

## Test File Organization

**Location:** every framework keeps its tests in a sibling `tests/` directory, not next to the sources:

```
Frameworks/text/
├── default.rave        # declares: tests tests/*.cc
├── src/
│   ├── trim.cc
│   └── trim.h
└── tests/
    ├── t_trim.cc       # tests for src/trim.cc
    ├── t_format.cc
    └── t_utf8.cc
```

**Naming:**
- Test source: `t_<unit>.cc` (C++) or `t_<unit>.mm` (Objective-C++), where `<unit>` mirrors the source file it tests: `tests/t_trim.cc` tests `src/trim.cc`; `tests/t_path.cc` tests `io/src/path.h`; `tests/t_storage.cc` tests `buffer/src/storage.h`.
- GUI tests (need AppKit and a display): `tests/gui_<name>.mm`. These are declared under `cxx_tests`, not `tests`, so they are built into a separate target. Example: `Frameworks/layout/tests/gui_layout.mm`.
- Test helper headers live in `tests/` with a `.h` extension and are included with a relative path: `Frameworks/parse/tests/support.h`, `Frameworks/theme/tests/CGColorRefToString.h`.
- Test functions: `test_<behavior>`, e.g. `test_trim`, `test_normalize`, `test_dot_files`, `test_random_insert`.
- Fixture functions: `setup_fixtures`, or `setup_<name>` for multiple setups.

**Glob rules (important):** each framework's `default.rave` decides which files in `tests/` are compiled. Some use `tests/*.cc`; others use `tests/t_*.cc` (e.g. `Frameworks/parse/default.rave`, `Frameworks/scm/default.rave`, `Frameworks/layout/default.rave`, `Frameworks/authorization/default.rave`, `Frameworks/SoftwareUpdate/default.rave`, `vendor/Onigmo/default.rave`). A non-`t_` file added to one of those directories is **silently not compiled**. Check the glob in that framework's `default.rave` before adding a test file.

**Basename rule:** `bin/gen_test` wraps each test file's body in `namespace <basename> { ... }`, using the file name without its extension. Name test files with valid C identifiers only (`t_trim`, not `t-trim`).

**Function signature rule:** `bin/gen_test` discovers tests by regex on the source text, `^\s*void (test_\w+) \(\)`. A test written with a different signature (for example `void test_x()` without the space, or with parameters) is **not registered and is silently skipped**. Use exactly `void test_<name> ()`, as in `Frameworks/io/tests/t_path.cc`.

**Structure:**

```
Frameworks/<name>/tests/
├── t_<unit>.cc        # one file per source unit, each with test_* functions
├── <helper>.h         # shared helpers, not compiled as a test on its own
└── gui_<name>.mm      # AppKit-dependent (only when the framework's default.rave declares cxx_tests)
```

## Test Structure

**Suite organization:** there is no suite class. Each file is a flat list of `void test_*()` functions in one namespace. Group related checks inside one function, and separate behaviors into separate functions. Example from `Frameworks/io/tests/t_path.cc`:

```cpp
#include <io/io.h>

void test_normalize ()
{
	OAK_ASSERT_EQ(path::normalize("//foo//"),                            "/foo");
	OAK_ASSERT_EQ(path::normalize("/foo/././."),                         "/foo");
	OAK_ASSERT_EQ(path::normalize("foo/../.."),                          "..");
	OAK_ASSERT_EQ(path::normalize(NULL_STR),                             NULL_STR);
}

void test_extensions ()
{
	OAK_ASSERT_EQ(path::strip_extension("foo.css.php"),           "foo.css");
	OAK_ASSERT_EQ(path::extension("/foo.bar/foo.css.php"),        ".php");
}
```

- Each test file includes the public header of the unit under test first: `#include <text/trim.h>` (`Frameworks/text/tests/t_trim.cc`). Use angle brackets for framework headers, and `"../src/..."` only when a test needs a private header (`Frameworks/scm/tests/t_git.cc` includes `"../src/drivers/api.h"`).
- Tables of input/expected pairs are written one assertion per line with the expected value column-aligned with spaces. See `Frameworks/text/tests/t_trim.cc` (14 cases in one function).
- Test functions use tab indentation and Allman braces, like product code (see CONVENTIONS.md).

**Setup and teardown:**
- A `void setup_fixtures ()` function runs once before any test in the file (`Frameworks/network/tests/t_download.cc`, `Frameworks/bundles/tests/t_query.cc`, `Frameworks/document/tests/t_grammar_fixtures.cc`, `Frameworks/parse/tests/t_anchors.cc`). Use it for process-wide state: starting a server, registering bundles, building a shared plist.
- Per-test isolation: construct a `test::jail_t` as a local variable. Its destructor removes the temporary directory (see Mocking/Fixtures below). Example: `test::jail_t jail;` inside `struct setup_t` in `Frameworks/scm/tests/t_git.cc`.
- Tests run **in parallel by default** (`dispatch_apply` in `bin/gen_test`). Do not share mutable globals between test functions in one file. Use `-P` to debug an ordering-dependent failure.

**Patterns:**
- Setup pattern: construct the fixture inline in the test body, or in `setup_*` for one-time work.
- Teardown pattern: RAII only. Put cleanup in a destructor (`jail_t` removes its directory; `Frameworks/scm/tests/t_git.cc` uses a local struct).
- Assertion pattern: `OAK_ASSERT_EQ(actual, expected)` with the actual value first, as in every file under `Frameworks/*/tests/`.

## Assertions

Defined in `bin/gen_test` and available to every test file (no include needed). Observed usage counts across `Frameworks/*/tests`:

| Macro | Uses | Purpose |
|---|---|---|
| `OAK_ASSERT_EQ(lhs, rhs)` | ~1,700 | Equality; prints both sides on failure |
| `OAK_ASSERT(expr)` | ~400 | Boolean assertion; also used as `OAK_ASSERT(false)` to flag an unexpected callback (`Frameworks/editor/tests/t_macro.cc`) |
| `OAK_ASSERT_NE`, `_LT`, `_LE`, `_GT`, `_GE` | ~12-50 | Relational; prints `Expected (lhs op rhs), found (...)` |
| `OAK_MASSERT_EQ(msg, lhs, rhs)` and `OAK_MASSERT(msg, expr)` | ~12 | Same, with a custom message first |
| `OAK_FAIL(msg)` | ~6 | Unconditional failure (e.g. setup failed in `Frameworks/scm/tests/t_hg.cc`) |
| `OAK_WARN(msg)` | ~2 | Prints a warning without failing |
| `OAK_ASSERT_STR_EQ(lhs, rhs)` | 1 | Defined locally in `Frameworks/bundles/tests/t_query.cc`; not a generic macro |

**How failures are reported:** the failing macro calls `oak_assertion_error`, which throws `oak_exception` (a `std::exception`). The runner catches it per test, stores the message (`file:line: Expected (...)`), and at the end prints `N of M tests failed:` followed by each message, then exits 1 (`bin/gen_test`). Other tests still run.

**Expected-failure and error-path testing:** no `OAK_ASSERT_THROWS` macro exists. To test an error return, assert on the returned value and the error string:

```cpp
std::string err;
OAK_ASSERT(!some_call(&err));          // some_call is a placeholder
OAK_ASSERT_EQ(err, "expected message");
```

(Error out-parameters are the project convention, see CONVENTIONS.md, "Error Handling".)

**Callback tests:** install a lambda that fails if called unexpectedly:

```cpp
editor.macro_dispatch(..., [](bundle_command_t const& cmd, ...){
	OAK_ASSERT(false); // Macro does not contain any commands
});
```

(`Frameworks/editor/tests/t_macro.cc`.)

## Mocking

**Framework:** none. No mocking library is used or available. `grep` for `mock`, `fake`, `stub` in `Frameworks/`, `Shared/`, `vendor/` finds only unrelated UI code (`fakeEvent` in `Frameworks/OakTextView/src/OakTextView.mm`).

**Patterns in use:**

1. **Subclass the interface with a local fake.** `Frameworks/network/tests/t_download.cc` defines `struct my_filter : filter_t` inside the test function and overrides `receive_status`, `receive_header`, and `receive_body` to capture values into references:

```cpp
void test_download ()
{
	struct my_filter : filter_t
	{
		my_filter (std::string& status, std::map<std::string, std::string>& headers, std::string& body) : _status(status), _headers(headers), _body(body) { }

		bool receive_status (std::string const& status)
		{
			_status = status;
			return true;
		}
		// ...
	};
	// ...
}
```

2. **Use a real local server instead of mocking HTTP.** `Shared/include/test/web_server.h` provides `web::setup_server(port)` and `web::run_server(root)`. `Frameworks/network/tests/t_download.cc` starts it on port `61706` in `setup_fixtures` on a detached `std::thread`. Hard-coding a port is the existing pattern; pick an unused one if you add a server test.

3. **Use real external tools inside a temporary directory.** `Frameworks/scm/tests/t_git.cc` initializes a real repository in `test::jail_t` and runs `git` via `io::exec("/bin/sh", "-c", script, nullptr)`. The git binary is located with `scm::find_executable("git", "TM_GIT")`. Tests in `Frameworks/scm/tests/` therefore require `git` (and `hg`/`svn` for `t_hg.cc`/`t_svn.cc`) on the machine.

4. **Build bundle state from plist text.** `Shared/include/test/bundle_index.h` (`test::bundle_index_t`) and the `static std::string` plist fixtures in `Frameworks/bundles/tests/t_query.cc` construct bundle items without touching `~/Library`.

**What to Mock:**
- Callbacks and interfaces (`filter_t`, `save_callback_ptr`, `bundle_command_t`) that a test needs to observe. Use a local `struct` subclass.
- Time-, network-, or process-dependent collaborators only when a real version is unavailable. Prefer the local web server over a stub when HTTP is involved.

**What NOT to Mock:**
- The filesystem. Use `test::jail_t` (`Shared/include/test/jail.h`).
- Plist, scope, regexp, and text parsing. These are pure C++ and are tested directly (`Frameworks/plist/tests/`, `Frameworks/scope/tests/`, `Frameworks/regexp/tests/`).
- SCM behavior. Use the real `git` in a jail (see pattern 3 above).

## Fixtures and Factories

**Test helpers in `Shared/include/test/`** (each is header-only, guarded, and in namespace `test`):

- **`jail.h`** (`test::jail_t`): a temporary directory under `path::temp("jail")`, removed in the destructor. Methods: `path(rel)`, `mkdir(rel)`, `touch(rel)`, `set_content(rel, text)`, `ln(src, dst)`, `remove(rel)`. Used by 19 files, including `Frameworks/file/tests/t_save.cc`, `Frameworks/io/tests/t_resolve.cc`, `Frameworks/scm/tests/t_git.cc`, `Frameworks/settings/tests/t_settings.cc`, and `Frameworks/bundles/tests/t_query.cc`.

```cpp
test::jail_t jail;
jail.set_content("dir/file.txt", "hello");
OAK_ASSERT(path::exists(jail.path("dir/file.txt")));
```

- **`web_server.h`**: `web::setup_server(port)` and `web::run_server(root)` for a local HTTP server serving files from a directory. Used by `Frameworks/network/tests/t_download.cc`.
- **`bundle_index.h`** (`test::bundle_index_t`): builds a bundle index from plist text for queries. Used by `Frameworks/bundles/tests/t_query.cc`, `Frameworks/parse/tests/t_anchors.cc`, `Frameworks/parse/tests/t_begin_while.cc`, `Frameworks/parse/tests/t_capture_rules.cc`, `Frameworks/selection/tests/t_brace_selection.cc`, `Frameworks/buffer/tests/t_buffer.mm`, `Frameworks/file/tests/t_bundle_fixtures.cc`, and `Frameworks/document/tests/t_grammar_fixtures.cc`.
- **`cocoa.h`**: GUI test scaffolding. `OakSetupApplicationWithView(view, testName)` creates an `NSApplication` and window. Tests are skipped unless the environment variable `GUI_TESTS` lists their name (`IsGUITestsEnabled` in `Shared/include/test/cocoa.h`). Only `gui_*.mm` files need this.

**Test data:**
- Inline strings are the default. Long plist fixtures are written as adjacent string literals in `static std::string const` variables (`Frameworks/editor/tests/t_macro.cc`).
- Grammar and bundle fixtures for parse/document tests are loaded from disk: `setup_fixtures` in `Frameworks/parse/tests/t_anchors.cc`, `Frameworks/document/tests/t_grammar_fixtures.cc`.

**Location:**
- Helpers: `Shared/include/test/`.
- Per-framework fixtures: inside that framework's `tests/` directory.
- No top-level `fixtures/` or `__fixtures__` directory exists.

## Common Patterns

**Async / threaded code:**
- Start the producer on a detached thread in `setup_*`, then assert on the result in the test. From `Frameworks/network/tests/t_download.cc`:

```cpp
void setup_fixtures ()
{
	if(!web::setup_server(WEB_SERVER_PORT))
	{
		fprintf(stderr, "*** unable to setup server for http://localhost:%d/\n", WEB_SERVER_PORT);
		abort();
	}
	std::thread([]{ web::run_server(path::join(__FILE__, "..")); }).detach();
}
```

- For waits on framework callbacks, use the framework's wait helper rather than `sleep`: `wait_for_status(info)` in `Frameworks/scm/tests/t_git.cc`.
- Do not use `sleep()` for synchronization in new tests.

**Error testing:**
- Assert on the returned error text or status, not on exceptions (the codebase does not throw in normal control flow):

```cpp
std::string err;
OAK_ASSERT(!some_call(&err));
OAK_ASSERT_EQ(err, "expected message");
```

- For fatal setup problems, print a `***`-prefixed message to `stderr` and `abort()` (see the `setup_fixtures` example above).

**Table-driven tests:**
- Put inputs and expected outputs in a sequence of `OAK_ASSERT_EQ` lines with the columns aligned. Example: `Frameworks/text/tests/t_trim.cc`, `Frameworks/io/tests/t_path.cc`.

**Environment-dependent tests:**
- Use `getenv` to read configuration. Do not hard-code machine paths; use `scm::find_executable` or `path::temp`.

## Adding a New Test (Checklist)

1. Create `Frameworks/<name>/tests/t_<unit>.cc` where `<unit>` matches the source file under test.
2. Check the `tests` glob in `Frameworks/<name>/default.rave`. Use a `t_` name if the glob is `t_*`.
3. Include the public header first: `#include <<name>/<unit>.h>`.
4. Write `void test_<behavior> ()` with exactly that signature (space before the parentheses, no parameters).
5. Use `test::jail_t jail;` for any file-system work; use a local struct subclass for callback capture.
6. Build and run: `ninja <name>/test`, then run the produced executable with `-v`.
7. Re-run with `-P` to confirm the test does not depend on execution order.

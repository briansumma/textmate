# Phase 1: Apple Silicon Build - Context

**Gathered:** 2026-10-19
**Status:** Ready for planning

<domain>
## Phase Boundary

A clean checkout of `develop` builds `TextMate.app` for arm64 on macOS 26.7.1 with Xcode 27.1. The build uses Homebrew dependencies under `/opt/homebrew` and no hand-edited `local.rave`.

Requirements in scope: BUILD-01, BUILD-02, BUILD-03, BUILD-04.

</domain>

<decisions>
## Implementation Decisions

### Homebrew Lookup (BUILD-02)
- `configure` asks `brew --prefix` for the Homebrew prefix. If `brew` is missing, it falls back to `/opt/homebrew`. No path is hardcoded.
- `configure` writes the Homebrew include and library paths to `local.rave`. `local.rave` is generated by `configure` and is never edited by hand.
- A missing dependency fails fast. The error prints the `brew install` command for that package.
- Package versions are recorded in the README Building section, taken from `brew list --versions`.

### Deployment Target and Flags (BUILD-04)
- Set `APP_MIN_OS` to `26.7.1` in `default.rave`, line 1. `default.rave` is the tracked file.
- Set `LSMinimumSystemVersion` to `26.7.1` in `Applications/TextMate/Info.plist`, if the plist sets that key. The planner checks this first.
- Keep `-std=c++2a` in `default.rave`, line 5. Change it only if the build fails.
- Do not add an explicit `-arch arm64` flag. An arm64 host builds arm64 by default.

### Clean Checkout, README, and Commits (BUILD-01, BUILD-03)
- Build output goes to `~/build/textmate`.
- The clean checkout is a new, empty directory. It comes from `git clone --recursive` of this local repository at `develop`, at the commit under test.
- The submodule command `git submodule update --init --recursive` goes in the existing `# Building` section of `README.md`, before the `./configure` step.
- Commits follow one commit per requirement ID. Each commit message names its requirement ID, as the feature-freeze check requires.

### Claude's Discretion
- None. All grey areas were accepted as recommended.

</decisions>

<code_context>
## Existing Code Insights

### Reusable Assets
- `local-orig.rave` contains arm64 and x86_64 target logic. Use it as a reference only. Do not copy it to `local.rave`. It sets a Developer ID identity and a notarize step (SIGN-01).

### Established Patterns
- `default.rave` holds the shared build settings. `configure` writes machine-specific settings to `local.rave`.
- `configure` checks dependencies with `test -f` and reports them with `error`. Keep that pattern for the Homebrew lookup (`configure:16-24`).

### Integration Points
- `configure:16-24`: the `/usr/local` include and library checks. They change to use the Homebrew prefix.
- `configure:16-17`: the `echo >> local.rave` lines that write the paths. They change to use the Homebrew prefix.
- `default.rave:1`: `APP_MIN_OS` (currently `10.12`).
- `default.rave:5`: `CXX_FLAGS` with `-std=c++2a`. Unchanged.
- `README.md:19`: the `# Building` heading. The submodule command goes here.
- `README.md:35-36`: the `brew install` line. Versions are recorded near it.
- `README.md:42`: the `./configure` and `ninja` instructions.

</code_context>

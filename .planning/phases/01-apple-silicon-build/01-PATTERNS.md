## Pattern Assignments

### `configure` (config, file-I/O)

**Analog:** `configure` itself. The prior change that introduced the
`local.rave` writer is commit `19c22714` (`Update ./configure script to write
rudimentary ‘local.rave’ file`). Use it as the reference for the shape of a
`configure` edit.

**Imports / shell header** (lines 1-3). Keep as is. `/bin/sh` is bash on macOS,
so the existing `[[ ]]` is fine.

```sh
#!/bin/sh
# set -u
function error () { printf >&2 "%s\n\nPlease see README.md for build instructions.\n" "$1"; exit 1; }
```

**Dependency check pattern** (lines 5-11). Fail fast with `which -s` and
`error`. Copy this style for the Homebrew tools.

```sh
for dep in capnp ninja ragel multimarkdown pgrep pkill; do
	which -s "$dep" || error "*** dependency missing: ‘${dep}’."
done
```

Note: `pgrep` and `pkill` ship with macOS (`/usr/bin/pgrep` verified). Do not
give them a `brew install` hint.

**Conditional `local.rave` write pattern** (lines 13-26). The write happens
only if `local.rave` does not exist. The header and library checks live in the
`else` branch.

```sh
if [[ -e local.rave ]]; then
	echo >&2 "Skipping writing ‘local.rave’: File already exists"
else
	echo >> local.rave 'add FLAGS    "-I/usr/local/include"'
	echo >> local.rave 'add LN_FLAGS "-L/usr/local/lib"'

	for hdr in boost/{crc,variant}.hpp capnp/{message,serialize-packed}.h sparsehash/dense_hash_map; do
		test -f "/usr/local/include/${hdr}" || error "*** dependency missing: ‘/usr/local/include/${hdr}’. Install dependency and/or update ‘local.rave’ with correct path."
	done

	for lib in capnp kj; do
		test -f "/usr/local/lib/lib${lib}."* || error "*** dependency missing: ‘/usr/local/lib/lib${lib}.*’. Install dependency and/or update ‘local.rave’ with correct path."
	done
fi
```

**Homebrew prefix lookup (NEW, no codebase analog).** Put this above the
`if [[ -e local.rave ]]` block, after the dependency loop. It follows the
`which -s` style of lines 9-11:

```sh
# Homebrew prefix: ask brew, fall back to the Apple Silicon default.
if which -s brew; then
	prefix="$(brew --prefix)"
else
	prefix="/opt/homebrew"
fi
```

**`local.rave` writes (CHANGE lines 16-17).** Replace `/usr/local` with
`${prefix}`. Double quotes are needed because the value is now expanded:

```sh
	echo >> local.rave "add FLAGS    \"-I${prefix}/include\""
	echo >> local.rave "add LN_FLAGS \"-L${prefix}/lib\""
```

**Header and library checks (CHANGE lines 19-25).** Two fixes apply here.

1. Replace `/usr/local` with `${prefix}`.
2. The library check must test one exact file. The current glob breaks on
   Homebrew. `test -f "/opt/homebrew/lib/libcapnp."*` expands to three files
   on this machine (`libcapnp.1.5.0.dylib`, `libcapnp.a`, `libcapnp.dylib`).
   `test` then gets too many arguments and exits 2, so `configure` reports a
   false "dependency missing". Verified with a two-file glob test in the
   scratchpad. Test the `.dylib` file directly. `libcapnp.dylib` and
   `libkj.dylib` both exist on this machine.

```sh
	for lib in capnp kj; do
		test -f "${prefix}/lib/lib${lib}.dylib" || error "*** dependency missing: ‘${prefix}/lib/lib${lib}.dylib’. Install with: brew install capnp"
	done
```

**Missing-dependency message (CHANGE, all checks).** The spec requires that the
error print the `brew install` command for that package. The current
`error` calls do not print one. Map each path to its formula:

| Check | Formula |
|-------|---------|
| `boost/*.hpp` | `boost` |
| `capnp/*.h`, `libcapnp`, `libkj` | `capnp` |
| `sparsehash/dense_hash_map` | `google-sparsehash` |
| `ninja`, `ragel`, `multimarkdown` (`which -s`) | same name |

Apply the same mapping to the `which -s` loop at lines 9-11, for the four
Homebrew tools only.

**Pre-existing issues. Leave them alone (surgical change).** Line 32 uses
`$builddir`, which is never set in `configure`. It is only honored when the
caller exports `builddir` and that directory exists (`configure:32-35`).

### `Applications/TextMate/Info.plist` (config, transform). NO EDIT

**Analog:** the file itself. The planner's first check in CONTEXT is answered
here. The key is set. Its value comes from a template variable, not a literal:

```xml
<key>LSMinimumSystemVersion</key>
<string>${APP_MIN_OS}</string>
```

The value is expanded at build time. `bin/rave:705-715` runs the
`ExpandVariables` compiler on `Info.plist`, passing `PLIST_FLAGS` from
`default.rave:25`. That flag includes `-dAPP_MIN_OS`. Changing
`default.rave:1` is enough.

Hardcoding `26.7.1` here would create a second source of truth. **Recommendation:
do not edit `Info.plist`.** Verify the built product instead:

```sh
plutil -extract LSMinimumSystemVersion raw "$(find ~/build/textmate -name TextMate.app -print -quit)/Contents/Info.plist"
```

This should print `26.7.1`. The source file will still show `${APP_MIN_OS}`,
which is expected.

## Shared Patterns

### Dependency check and fail-fast error
**Source:** `configure:3, 9-11, 19-25`
**Apply to:** every new or changed check in `configure`
```sh
test -f "<path>" || error "*** dependency missing: ‘<path>’. <install hint>"
which -s "<tool>" || error "*** dependency missing: ‘<tool>’."
```
Keep the `error` helper. It exits non-zero and points to README.md, which
satisfies the fail-fast decision.

### Single source for the deployment target
**Source:** `default.rave:1` (value), `default.rave:25` (`PLIST_FLAGS` into the
plist template), `Applications/TextMate/Info.plist:32` (consumer)
**Apply to:** BUILD-04. Change only `default.rave:1`. Do not hardcode the
version anywhere else.

### Generated, never hand-edited local configuration
**Source:** `configure:13-26` writes `local.rave`. `.gitignore:2` lists it.
**Apply to:** BUILD-02. Behavior to know: if `local.rave` already exists,
`configure` skips the write and keeps the old paths. The clean clone in
BUILD-01 avoids this. Do not edit `local.rave` by hand, and do not commit it.

### Commit convention
**Source:** `.planning/codebase/CONVENTIONS.md:377-383`, and the commit history
on `develop`
**Apply to:** all Phase 1 commits
- Summary under 70 characters, imperative mood, no trailing period.
- One commit does one thing.
- Blank line, then the reason if it is not obvious.
- The history on `develop` does not use requirement IDs. CONTEXT requires the
  ID in each message, so use a form like `BUILD-04: set deployment target to
  26.7.1`. Confirm the form with the user if the feature-freeze check needs a
  different one.

## Gotchas for the Planner

1. **Glob in `test -f`** (`configure:24`). Breaks on Homebrew, as described
   above. Test the `.dylib` file directly. This is the only real bug found in
   the target files, and it is in scope for BUILD-02.
2. **Build output path.** CONTEXT says `~/build/textmate`. `README.md:79` says
   `~/build/TextMate`. `configure` passes `-b` only when the exported
   `builddir` names an existing directory (`configure:32-35`). The planner
   should have the executor `mkdir -p ~/build/textmate` first, then run
   `builddir="$HOME/build/textmate" ./configure`. Verify this when executing.
3. **`Info.plist` needs no edit.** See above. The CONTEXT check ("if the plist
   sets that key") is satisfied through `${APP_MIN_OS}`.
4. **`.github/workflows/build.yml`** lists the same brew formulas. It is a
   GitHub Actions file for a Bitbucket-hosted repo and is out of scope. Do
   not modify it. It is a reference for the package list only.
5. **Line numbers drift.** CONTEXT cites `README.md:42` for `./configure`. The
   command is at `README.md:47`. Use the content, not the number.

<flagged_assumptions>
## Flagged assumptions and edge-probe dispositions (this plan)

- **Edge probe, RUN-03 "adjacency".** Two bundles with exactly equal names are not counted twice. The seven managed copies of user bundles are excluded by exact name (REQUIREMENTS Definitions). A user bundle that shares a name with a managed bundle is one bundle, layered over that copy. Shell Script 2 has no managed twin, so it is not excluded. Disposition: resolved by the requirement's own definition.
- **Edge probe, RUN-03 "empty".** A bundle with no command runs nothing and gets a NO-COMMAND row. Plan 05 loads it in the GUI. A bundle with no grammar, theme, or snippet at all (the five NOFILE bundles) cannot load under the corrected rule. Disposition: FAIL with cause "no grammar, theme, or snippet file" under B1 (settled).
- **Edge probe, RUN-03 "ordering".** Bundles are processed in LC_ALL=C sorted order, and the first command is the first merged file in the same order. Each bundle's result is independent, so the processing order cannot change the pass rule. Disposition: resolved.
- **A-03 (assumption).** "First command it declares" means first in filename order, not menu order. Brian approves this in Decision A.
- **A-04 (assumption).** A user bundle that shares a name with a managed bundle is a delta over that managed copy. Inferred from the HTML.tmbundle layout (two .tmCommand deltas with isDelta set, and an info.plist of 289 bytes). Brian approves this in Decision A.
- **A-05 (assumption, GUI decides, binding).** Headless runs, with env -i and the TM_ variables set, approximate what TextMate passes to a command. A missing input (for example a selection) can make a command fail headlessly even though it works in the GUI. Rule: the GUI target check in plan 05 is the verdict for each command. A headless non-zero exit is recorded as a note and does not set the verdict.
</flagged_assumptions>
